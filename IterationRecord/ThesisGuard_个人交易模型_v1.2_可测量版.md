# ThesisGuard｜个人交易模型 v1.2（可测量版）

> **定位：A股产业趋势型个人交易系统**  
> **核心风格：产业预期差 + 趋势右侧确认 + 风险仓位 + 结构止损 + 账户级风险控制**  
> **版本：v1.2**  
> **目标：减少模糊词、减少自由裁量、提高可测量性、提高复盘一致性**

---

# 0. v1.2 核心原则

本版本不再满足于“看起来合理”。任何重要交易条件必须尽量满足：

1. **交易前可以判断 PASS / FAIL；**
2. **交易后可以复盘是否按规则执行；**
3. **不同时间复核时，结论尽量一致。**

因此：

> **所有模糊词必须尽量被阈值、区间、相对比较或状态机替代。**

例如：

- “放量” → `当日成交量 / 20日均量`；
- “缩量” → `回踩成交量 / 突破日成交量`；
- “转强” → 收盘重新站上关键位 + 60分钟结构确认；
- “弱市” → Market Regime Score；
- “预期差” → Consensus vs My View；
- “好买点” → Setup + Trade Score + Hard Veto。

---

# 1. 模型总纲

完整决策链：

> **Market Regime → Candidate Score → Thesis Gap → Setup → Trade Score → Hard Veto → Position Sizing → Execution → Review → Statistics → Iteration**

稳定盈利公式：

> **长期正期望 = 模型优势 × 风险控制 × 市场适配 × 执行一致性 × 足够样本**

本模型不追求：

- 每笔赚钱；
- 猜最低点；
- 卖在最高点；
- 追求最高胜率；
- 用单笔结果评价模型。

本模型追求：

> **小亏可控、盈利放大、规则可重复、样本可统计。**

---

# 2. 股票分类

任何股票进入交易模型前必须分类。

## A 类：产业趋势型

满足以下 4 项中的至少 3 项：

- 行业景气有公开数据支持；
- 最近 2–4 个季度存在盈利改善或盈利预期上修；
- 订单 / 产品 / 价格 / 产能中至少一项出现可验证变化；
- 市场存在持续性机构趋势资金参与迹象。

这是主要交易对象。

## B 类：产业 + 事件混合型

需同时满足：

- 有真实产业逻辑；
- 有事件催化；
- 事件可能影响未来 1–4 个季度盈利或估值中枢。

若事件只影响短期情绪，不改变盈利预期：

> 不按 B 类加分。

## C 类：纯情绪 / 游资型

主要依赖：

- 连板；
- 龙头；
- 题材；
- 卡位；
- 情绪周期；
- 市场记忆。

本模型默认不把 C 类作为主要盈利来源。

# 3. 候选池评分：Candidate Score

用于回答：

> **这家公司是否值得等待？**

固定使用以下 100 分体系，不修改权重：

| 维度 | 权重 |
|---|---:|
| 产业景气 | 20 |
| 盈利质量与季度加速度 | 25 |
| 订单 / 产品竞争力 | 20 |
| 财务质量 | 15 |
| 估值合理度 | 10 |
| 市场确认 | 10 |
| **合计** | **100** |

解释：

- **≥80：核心候选**
- **70–79：观察候选**
- **60–69：普通观察**
- **<60：淘汰**

注意：

> Candidate Score 用于候选排序，不直接授予“可交易资格”。

不得因为以下因素直接加分：

- 市值较小；
- “翻倍空间”；
- 知名投资人持仓；
- 大V / 博主推荐；
- 单日涨停。

# 4. Fundamental Core（交易阶段使用）

为避免 Candidate Score 中“市场确认”与后面的 Trade Score 重复计分，正式交易阶段只抽取前五项：

- 产业景气 20
- 盈利质量与季度加速度 25
- 订单 / 产品竞争力 20
- 财务质量 15
- 估值合理度 10

合计 90 分。

归一化：

```text
FundamentalCore = 前五项得分 / 90 × 100
```

例如前五项得分 75：

```text
75 / 90 × 100 = 83.3
```

Candidate Score 仍保持原六项固定体系；Fundamental Core 只是交易阶段的派生指标，不修改候选评分规则。

# 5. 预期差量化：Thesis Gap

任何核心候选都必须填写：

## 5.1 Consensus

市场一致预期：

- 未来 1 年净利润；
- 未来 2 年净利润；
- 收入增速；
- 毛利率；
- 关键产品价格假设；
- 核心行业供需假设。

## 5.2 My View

自己的预测必须基于可验证事实：

- 未来 1 年净利润；
- 未来 2 年净利润；
- 收入增速；
- 毛利率；
- 核心订单 / 产品 / 价格 / 产能假设。

## 5.3 Earnings Gap

```text
EarningsGap = (MyViewProfit - ConsensusProfit) / ConsensusProfit
```

初始分类：

- **<5%：无明显预期差**
- **5%–10%：轻微预期差**
- **10%–20%：中等预期差**
- **>20%：强预期差**

若无法获得可靠一致预期：

> 标记 `UNKNOWN`，不得把“股价没涨”自动解释成预期差。

# 6. 预期差证据等级

## Level A：强证据

- 公司公告；
- 财报；
- 订单公告；
- 官方价格 / 行业数据；
- 明确产能数据；
- 客户认证 / 量产公告。

## Level B：中等证据

- 多家券商交叉验证；
- 高质量产业链调研；
- 可靠行业价格数据；
- 多来源一致信息。

## Level C：弱证据

- 单一媒体；
- 博主；
- 市场传闻；
- 未证实调研纪要。

规则：

> **只有 A / B 级证据可以进入正式 Thesis。**

# 8. Market Regime 评分细则

## 8.1 主要指数趋势 25

以沪深300 / 中证1000 / 创业板指综合判断：

- 20 日线向上且多数指数站上 MA20：20–25
- 指数围绕 MA20 震荡：10–19
- 多数指数跌破 MA20 且 MA20 向下：0–9

## 8.2 涨跌家数 20

以全市场上涨家数占比：

- ≥65%：18–20
- 55%–65%：14–17
- 45%–55%：9–13
- 35%–45%：5–8
- <35%：0–4

## 8.3 成交额趋势 15

```text
TurnoverRatio20 = 当日成交额 / 20日平均成交额
```

- ≥1.20 且指数走强：13–15
- 0.95–1.20：8–12
- 0.75–0.95：4–7
- <0.75：0–3

## 8.4 主线持续性 20

强持续必须尽量满足：

- 连续 3–5 个交易日存在明确主线；
- 主线龙头 / 中军未明显破位；
- 板块内部至少有多只趋势股共振。

评分：

- 强持续：16–20
- 有主线但轮动快：9–15
- 无持续主线：0–8

## 8.5 高位股 / 赚钱效应 10

参考：

- 强势股次日承接；
- 趋势股创新高比例；
- 高位股是否普遍补跌。

## 8.6 跌停 / 大跌数量 10

跌停、大跌数量越多，得分越低。

# 9. Market Regime 状态

- **GREEN：≥70**
- **YELLOW：40–69**
- **RED：<40**

### GREEN

允许 Setup A / B / C。

账户整体仓位参考：

> **60%–80%**

### YELLOW

> **Setup B：上涨趋势缩量回踩**

账户整体仓位参考：

> **30%–60%**

### RED

只允许：

- Trade Score 很高的逆势强标的；
- 或直接空仓。

账户整体仓位参考：

> **0%–30%**

# 10. 日线上升趋势定义

必须满足以下至少 3 项：

1. 收盘价 > MA20；
2. MA20 > MA60；
3. MA20 最近 5 个交易日斜率为正；
4. 最近一个主要低点高于前一个主要低点；
5. 最近一个主要高点不低于前一个主要高点。

状态：

- 4–5 项：`STRONG_UPTREND`
- 3 项：`UPTREND`
- <3 项：不定义为上升趋势

---

# 11. 平台定义

Setup A 的平台必须满足：

1. 横盘至少 **10 个交易日**；
2. 平台宽度：

```text
RangeWidth = (平台高点 - 平台低点) / 平台中位价
```

默认：

> **RangeWidth ≤15%**

3. 至少出现 2 次以上对上沿 / 下沿的有效测试；
4. 不允许使用 3–5 天的小整理冒充平台。

---

# 12. 放量定义

```text
VolumeRatio20 = 当日成交量 / 20日平均成交量
```

分类：

- <1.0：未放量
- 1.0–1.2：轻微放量
- 1.2–1.5：有效放量
- >1.5：明显放量

Setup A 默认突破要求：

> **VolumeRatio20 ≥1.2**

---

# 13. 缩量定义

```text
PullbackVolumeRatio = 回踩日成交量 / 突破日成交量
```

默认：

> **PullbackVolumeRatio ≤0.75**

或者：

```text
回踩日成交量 / 20日均量 ≤1.0
```

两者满足任意一项，可定义为缩量。

---

# 14. Setup A：平台突破回踩（量化版）

必须按顺序验证。

## A1. 平台形成

- 平台 ≥10 个交易日；
- RangeWidth ≤15%。

## A2. 突破

同时满足：

1. 收盘价 > 平台高点；
2. 突破幅度：

```text
BreakoutPct = (收盘价 - 平台高点) / 平台高点
```

默认：

> **BreakoutPct ≥1%**

3. VolumeRatio20 ≥1.2。

## A3. 回踩

突破后 **1–8 个交易日** 内出现回踩。

要求：

- 最低价允许短暂跌破平台上沿；
- 不得连续 2 个交易日收盘低于平台上沿；
- 回踩日成交量满足缩量定义。

## A4. 再确认

满足任一：

- 日线收盘重新站上突破日收盘价；
- 60分钟收盘突破回踩后的局部高点；
- 60分钟形成 Higher Low + Higher High。

满足 A1–A4：

> `Setup A = TRIGGERED`

---

# 15. Setup B：上涨趋势缩量回踩（量化版）

## B1. 趋势

日线上升趋势评分 ≥3/5。

## B2. 回踩位置

价格回到以下至少一个区域：

- MA20 ±3%
- 前高 ±3%
- 前突破平台 ±3%
- 最近关键低点上方 0%–3%

## B3. 回调幅度

从最近波段高点回撤：

> **默认 3%–12%**

超过 15%：

> 不再自动视为健康回踩，需重新评估趋势。

## B4. 缩量

满足缩量定义。

## B5. 止跌确认

满足任一：

- 日线收盘高于前一交易日最高价；
- 60分钟形成 Higher Low；
- 60分钟突破回踩期间局部高点。

满足 B1–B5：

> `Setup B = TRIGGERED`

---

# 16. Setup C：催化后的第一次健康调整（量化版）

## C1. 催化证据

必须为 A / B 级证据。

## C2. 催化后第一波上涨

催化后 1–10 个交易日内累计涨幅：

> **默认 ≥8%**

若不足 8%：

> 不定义为“第一波”。

## C3. 第一次调整

调整幅度：

> **默认 5%–15%**

## C4. 成交量

调整期间平均成交量：

> **≤上涨阶段平均成交量的 80%**

## C5. Thesis 未失效

催化事实仍成立。

## C6. 再转强

使用 Setup B 的止跌确认。

满足 C1–C6：

> `Setup C = TRIGGERED`

---

# 17. “转强”统一定义

满足以下任一客观条件：

1. 日线收盘高于前一交易日最高价；
2. 60分钟形成 Higher Low + Higher High；
3. 60分钟收盘突破最近 2–3 根 K 线局部高点。

不得仅因为：

- 分时拉升；
- 盘中翻红；
- 单根快速上涨；

就认定为转强。

# 21. Hard Veto｜硬性否决

以下任意一项出现：

> **直接不交易。**

1. 无明确止损位；
2. R/R <1.5；
3. Thesis 已被证伪；
4. Portfolio Heat 超限；
5. 同产业风险超限；
6. 重大事件风险未评估；
7. 财务 / 订单关键事实无法确认；
8. RED 市场且 Trade Score <85；
9. 计划外临盘追涨；
10. 当前心理状态明显急于回本 / 报复性交易。

Hard Veto：

> **不允许被高评分抵消。**

---

# 22. R/R 计算规则

目标价不得为了满足 2R 倒推。

目标必须先由客观结构确定，优先级：

1. 前高；
2. 重要压力区；
3. 历史成交密集区；
4. 合理估值对应价格；
5. 波动区间 / ATR；
6. 产业逻辑对应估值情景。

然后：

```text
RR = (目标价 - 买入价) / (买入价 - 止损价)
```

正常要求：

> **RR ≥2**

Hard Veto：

> **RR <1.5**

---

# 23. 1R 与仓位

定义：

> **1R = 单笔计划允许的最大亏损。**

默认：

- 正常：账户净值 **0.5%–0.8%**
- 极限：**1%**

仓位：

```text
PositionValue = 账户净值 × 风险比例 / 止损幅度
```

---

# 24. Portfolio Heat

```text
PortfolioHeat = 所有未平仓交易最大计划亏损之和 / 账户净值
```

限制：

### GREEN

> ≤3%

### YELLOW

> ≤2%

### RED

> ≤1.5%

---

# 25. 同产业风险

高度相关标的总风险：

- GREEN：≤2%
- YELLOW：≤1.5%
- RED：≤1%

例如 PCB / CCL / AI 硬件高度相关持仓：

> 不能简单视为独立风险。

---

# 26. Gap / Event Risk｜跳空与事件风险

以下事件前必须评估：

- 财报；
- 重大业绩预告；
- 监管结果；
- 重大合同公告窗口；
- 重要行业政策；
- 海外重大宏观事件；
- 其他可能造成隔夜跳空的高波动事件。

风险调整：

- 普通：EventRiskFactor = 1.0
- 中等事件风险：0.75
- 高事件风险：0.5

例如原风险预算 0.8%，高事件风险：

```text
0.8% × 0.5 = 0.4%
```

---

# 27. 流动性过滤

默认要求：

> **计划仓位金额 ≤ 个股20日平均日成交额的 0.5%**

对小资金通常不构成限制，但规则保留。

真实收益统计应扣除：

- 佣金；
- 印花税；
- 滑点。

---

# 28. 加仓规则

只允许盈利 / 正确交易加仓。

必须同时满足：

1. 原 Thesis 未变；
2. 原 Setup 未失效；
3. 当前价格不低于平均持仓成本的 -0.5R；
4. 出现新的结构确认；
5. Portfolio Heat 未超限；
6. 加仓后整体止损仍可定义。

禁止：

> **为降低成本而加仓。**

---

# 29. Re-entry｜重新入场

第一次止损不影响第二次信号。

允许重新入场，必须满足：

1. 原 Thesis 未失效；
2. 新 Setup 从头重新满足；
3. 新失效位明确；
4. 新 R/R 达标；
5. 不允许因为“想把亏损赚回来”而降低标准。

原则：

> **上一笔亏损与下一笔是否值得交易，逻辑上相互独立。**

---

# 30. 时间止损（按 Setup 分开）

v1.2 初始默认：

- Setup A：**3–5 个交易日**
- Setup B：**5–10 个交易日**
- Setup C：**3–6 个交易日**

若达到时间窗口仍未产生：

- 至少 +0.5R 的 MFE；
- 或明显结构推进；

标记：

> `TIME_DECAY`

进入减仓 / 退出评估。

以上时间参数属于待验证参数。

---

# 31. 止损类型

## 31.1 结构止损

首选。

## 31.2 逻辑止损

Thesis 被事实证伪。

## 31.3 时间止损

Setup 长时间不兑现。

原则：

> **不因“不想亏”扩大止损。**

# 32. 盈利管理

当前保留：

- +1R：正常持有；
- +1.5R～2R：上移保护位；
- +2R：可考虑减仓约 1/3；
- 剩余仓位趋势跟随。

但：

> **“+2R 减 1/3”是待验证参数，不是永久铁律。**

未来由 MFE 数据决定是否修改。

---

# 33. MFE / MAE

## MFE

```text
MFE = (持仓期间最高有利价格 - 买入价) / 1R对应价格幅度
```

## MAE

```text
MAE = (买入价 - 持仓期间最低不利价格) / 1R对应价格幅度
```

用途：

- MFE 高、实际盈利低 → 可能过早止盈；
- MAE 长期很小 → 可能止损过宽；
- MAE 经常 >1R → 买点 / 止损设计存在问题。

# 34. 回撤降速

账户净值从历史高点计算。

## 回撤 <3%

正常。

## 回撤 ≥5%

单笔风险上限：

> **0.5%**

## 回撤 ≥8%

总仓位降低约一半。

只允许：

> **Trade Score ≥85**

## 回撤 ≥10%

暂停主动新开仓。

必须复盘：

- 最近 20 笔；
- Setup 分布；
- 执行率；
- Market Regime；
- 是否出现模型失效。
