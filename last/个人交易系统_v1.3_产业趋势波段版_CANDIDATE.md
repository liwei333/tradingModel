## 1. 版本治理与优先级

### 1.1 状态含义

| 状态 | 在本文中的含义 |
|---|---|
| `ACTIVE BASELINE` | 完整引用 v1.2 当前正式模块，不改变其任何条件；该标签不使 v1.3 整体生效 |
| `CANDIDATE` | 已写入候选框架，等待验证和人工决议 |
| `SHADOW` | 按冻结定义记录假设信号或平行结果，不下单、不改真实保护价、不占实验名额 |
| `SHADOW（DEFER）` | 可以记录，但本阶段暂缓进入任何实盘试行评估 |
| `CANDIDATE（DEFER）` | 当前只保留议题，不建立新的实际交易通道 |

### 1.2 冲突处理

1. 真实账户、既有订单、持仓保护、退出和统计归属，始终以每笔交易事前登记的 v1.2 及其原始记录为准。
2. 本文与 v1.2 出现任何冲突时，v1.2 优先；冲突记入 Candidate 问题清单，不能在盘中自行选择较宽松口径。
3. `SHADOW` 结果只能写入独立验证账本。它不能创建、撤销或修改券商订单，不能占用或释放 v1.2 的 EXPERIMENTAL 槽位，也不能改变 H、CashPool、RecoveryHeadroom 或真实账户状态。
4. 改动 A、C、Trend Hold 或行业确认的任一参数时，新建候选规则集编号。看过结果后修改的旧样本只用于设计，不继续作为新版本的未见验证样本。
5. 本文转为正式版本必须经过人工确认，并另行建立正式文件或明确的状态变更；不得仅删除文件名中的 `CANDIDATE` 字样宣称生效。

## 4. 产业 Thesis 与行业确认接口

### 4.1 产业 Thesis 卡

每个 A/B/C 验证信号关联一张产业 Thesis 卡：

```text
ThesisID / SecurityID / IndustryBenchmarkID / ClassificationVersion
ThesisHorizon = 未来1～2个季度
KeyMetrics = 2～4个可核对指标
每项：当前值 / 可比市场预期 / Base / Bull / Bear / 来源 / 发布时点 / 取得时点 / 下一验证日
ThesisGap = 自有Base与可比市场预期的差异；不可比时为UNKNOWN
Catalysts = 可能验证产业传导的事件与窗口
Invalidation = 否定订单、盈利或产业传导的客观事实与阈值
EvidenceStatus = VERIFIED / UNVERIFIED / STALE / CONFLICTING / MISSING
```

对 ACTIVE BASELINE 的 Setup B，这些新增字段先作为研究增强和验证字段；缺失不会在本 Candidate 阶段改变 v1.2 的正式准入结果。对 A/C SHADOW，Thesis 卡不完整则影子信号记 `UNKNOWN`，不纳入可比较的完整信号分母。

### 4.2 行业确认候选

行业基准代码、分类版本、数据源和信息截止时点必须在信号判断前冻结。无可靠行业指数或窗口不足时，状态为 `UNKNOWN`。

```text
IndustryConfirm(t) =
    Close_industry(t) > MA20_industry(t)
and MA20_industry(t) > MA20_industry(t-5)
and Ret20_industry(t) > Ret20_CSI1000(t)
```

`IndustryConfirm` 当前状态为 `SHADOW`。它不改变 NORMAL、EXPERIMENTAL 或 RED 的正式判断，也不为 A/C 产生实际交易许可。

## 6. Setup A：首次平台突破 SHADOW

### 6.1 信号条件

设 t 为完整信号日，所有 OHLC、均线和成交量使用同一登记尺度：

```text
1. v1.2共同研究、事件、账户条件可核对；NORMAL市场过滤PASS且非RED。
2. 产业Thesis卡完整；IndustryConfirm单独记录，不作为当前硬门槛。
3. 平台窗口固定为t-20…t-1：
   PlatformHigh = max(High)
   PlatformLow  = min(Low)
   PlatformWidth = PlatformHigh / PlatformLow - 1 <= 15%
4. MA20(t) >= MA20(t-5)
5. MA60(t) / MA60(t-10) - 1 >= -1%
6. Close(t) >= 1.01 × PlatformHigh
7. Volume(t) >= 1.2 × AvgVolume(t-20…t-1)
8. v1.2既有OVERHEATED任一项均未触发，全部输入可核对。
```

### 6.2 影子计划

```text
有效期：仅t+1
Entry条件：t+1仍高于PlatformHigh，假设成交价不得高于Pmax
Pmax：min[换算后Close(t)×1.01，事前影子卡预设的价格上限]
S0：严格低于min[Low(t), PlatformHigh]的最近合法报价
Target：独立的前高、压力区或有过程的估值情景；不得按2R倒推
RR：扣费用和不利成交预留后>=2
ShadowRiskCap：0；不得真实下单
FuturePilotCap：仅在后续正式决议允许时，最多为当时NORMAL单笔预算的0.5倍
```

Thesis、平台、均线、量能、过热、S0、Target、RR 或账户任一必需输入为 FAIL/UNKNOWN，影子结果记失败或未知；`IndustryConfirm` 仍只记录 SHADOW 状态，不作为本候选的硬门槛。信号后至假设建仓完成前触及 S0、可靠事实证伪或账户暂停，信号失效；t+1 无合规假设成交则 `EXPIRED`，不得跨日补入。

过热定义直接复用 v1.2 已有涨停、一字板、3 日涨幅、5 日涨幅、距 MA20、连续大阳、巨量加速和情绪高潮字段，不另建第二套追高标准。

## 7. Setup C：趋势中继 SHADOW（DEFER）

### 7.1 信号条件

```text
1. v1.2共同研究、事件、账户条件可核对；NORMAL市场过滤PASS且非RED；Thesis仍有效。
2. Close(t-1)>MA20(t-1)>MA60(t-1)，且MA20(t-1)>MA20(t-6)。
3. 在N=20向下到N=7中，选择满足下式的最大N并冻结：
   PlatformWidth(N)=maxHigh(t-N…t-1)/minLow(t-N…t-1)-1 <= 8%
   不存在N则FAIL。
4. PlatformHigh、PlatformLow由冻结N唯一确定。
5. Close(t)>=1.01×PlatformHigh。
6. Volume(t)>=1.2×平台N日平均成交量。
7. Close(t)/MA20(t)-1<=10%，且v1.2既有OVERHEATED均未触发。
```

### 7.2 影子计划

```text
有效期：仅t+1
Entry条件：t+1保持在PlatformHigh之上，假设成交价不得高于Pmax
Pmax：min[换算后Close(t)×1.01，事前影子卡预设上限]
S0：严格低于PlatformLow的最近合法报价
Target：独立压力或估值依据
RR：扣成本后>=2
ShadowRiskCap：0；不得真实下单
FuturePilotCap：只有后续正式决议允许时，最多为当时NORMAL单笔预算的0.5倍
```

任何必需字段 UNKNOWN、t+1 回落触及 S0、Thesis 证伪、RED、账户阻断、RR 不足或过热均失败。合法最小股数超出假设预算时直接放弃，不能缩窄 S0。C 的排期为 `DEFER`，达到样本数也不会自动进入实盘试行。

## 8. Trend Hold：盈利保护 SHADOW

Trend Hold 仅对按 v1.2 实际持有、曾达到相应阶段的 NORMAL 交易平行计算。所有价位先按公司行动转换到同一尺度；候选保护价只上移、不下移。v1.2 的价格、Thesis、账户退出及真实保护位始终优先，影子计算不能延迟真实退出。

```text
阶段0：收盘尚未达到Entry0+1×r0
  ShadowStop = 原S0

阶段1：首次收盘达到Entry0+1×r0
  下一交易日一次性计算：
  S_1R = max[旧ShadowStop, 严格低于触发日及此前4个完整交易日最低价的最近合法报价]
  此后冻结，不逐日滚动，直到阶段2或其他退出。

阶段2：首次收盘达到Entry0+2×r0，进入TREND_HOLD
  每日盘前：
  BaseTrendLevel = min[前一完整日MA20, 前10个完整交易日最低价]
  Candidate10 = 严格低于BaseTrendLevel的最近合法报价
  ShadowStop = max[旧ShadowStop, Candidate10]

阶段3：持仓完整日触发任一v1.2既有OVERHEATED价格/量能条件
  锁定ACCELERATION_PROTECT；下一交易日起：
  Candidate5 = 严格低于前5个完整交易日最低价的最近合法报价
  ShadowStop = max[旧ShadowStop, Candidate5]
  该状态不因回落而关闭。
```

验证账本同时计算三条可比较路径：v1.2 当前 5 日低点、完整 Trend Hold 候选、简化的 +2r 后 10 日低点。三条路径使用同一入场、数量、费用、Thesis 退出和账户退出；不得给某一路径使用事后更有利的成交或事件信息。

3. 最近连续 20 笔合规交易中，拖延止损、下移止损、亏损补仓和超计划数量均为 0；

## 12. Historical Regime Study：研究与持有语境 SHADOW

### 12.1 定位与权限边界

Historical Regime 的主要性质是 `Research Context` 与 `Holding Context`，其次用于检验 Trend Hold。它不属于 Alpha 信号，不是 Setup 输入、准入门、S0 生成器或风险额度调节器。其输出只回答“这个证券过去在相似产业与价格阶段怎样波动，以及当前比较的局限是什么”，不回答“可以买或不能买”。

以下优先级不可改变：

```text
Thesis / Setup / RED / AccountRiskState / S0 / RR / PositionSize / EXIT_PENDING
    > Historical Regime
```

即使历史比较为高置信度相似，任一正式门禁为 FAIL 或 UNKNOWN 时，Historical Regime 都不能将其改成 PASS；已经触发的核心退出也不能因为历史回撤曾经更深而延期。Historical Regime 为 UNKNOWN 时，只表示研究语境不足，不否决或放行一笔原本由 v1.2 决定的交易。

### 12.2 时点化规则

每张卡冻结 `CutoffTimestamp`。价格、指数、行业、财务、公告和公司行动数据只有在 `AvailableAt <= CutoffTimestamp` 时才能进入该时点的判断。信号日 t 只使用 t 日及以前的完整数据；任何 t+1 以后数据进入输入，`StudyStatus=FAIL` 且 `FailureReason=FUTURE_DATA`。

当前复权序列若包含研究截止日之后才发生的公司行动，只可用于跨期描述；历史时点判断必须使用当时可得的复权快照，或只使用对统一比例变换不敏感的收益率、均线顺序和相对位置，并明确局限。用事后高低点切分周期时，必须标记 `SegmentationMode=EX_POST_DESCRIPTIVE`，不得把事后标签伪装成当日已知状态或用于模拟交易许可。

### 12.3 最小 Historical Regime Card

```text
HistoricalRegimeID / SecurityID / CardVersion
StudyStartDate / StudyEndDate / CutoffTimestamp
PriceDataSource / IndustryDataSource / FundamentalDataSource
```

### 12.4 阶段解释

阶段标签只服务数周至数月的大波段研究：

| Historical Regime | 允许的研究用途 | 对正式动作的影响 |
|---|---|---|
| `BASE` | 研究筑底持续时间、量能与 Thesis 变化顺序 | 无；不能据此猜底 |
| `EARLY_TREND` | 研究启动与假突破 | 无；实际入场仍需 v1.2 Setup |
| `MARKUP` | 研究强趋势回撤和持有 | 无；不能放宽 S0 或忽略过热 |
| `CONSOLIDATION` | 研究中继、Trend Hold 与 T_OVERLAY 影子资格 | 只产生影子观察资格 |
| `DISTRIBUTION` | 提醒复核 Thesis、量价与退出路径 | 不自行触发或取消退出 |
| `DOWNTREND` | 研究趋势破坏及历史恢复时间 | 不能成为补仓或继续持有失效 Core 的理由 |
| `UNKNOWN` | 暴露资料或分类不足 | 不产生交易许可 |

## 13. T_OVERLAY：核心仓之上的战术层 SHADOW

### 13.1 三类仓位动作必须分离

```text
CORE_SWING != T_OVERLAY != AVERAGING_DOWN
```

`CORE_SWING` 保存产业 Thesis、原始 Entry0/R0/S0、战略数量、Trend Hold 与最终退出。`T_OVERLAY` 使用独立 `TOverlayID/TTradeID`，只评估短时战术往返。因下跌增加期末战略数量、未完成第二腿却把多出的股份改名为 Core、重置 Entry0/R0/S0 或下移保护价，均为 `AVERAGING_DOWN` 或计划外新增风险，继续禁止。

初始影子研究只允许**正 T**：先假设买入战术股份，再假设卖出等量、昨日已持有且真实可卖的 Core 批次。**反 T**（先卖 Core、再等待买回）在本候选中 `DEFER`，因为它会在上行突破时直接丢失核心敞口，和该交易者“尽量持有主要产业波段”的目标冲突。

### 13.2 影子资格

只有以下输入全部可核对时，才可从 `T_SKIPPED` 进入 `T_READY`：

1. 存在 `ObjectClass=NORMAL` 的 `CORE_SWING`，`CoreShares>0`；`EXPERIMENTAL`、`LEGACY_PRE_MODEL` 与 `LONG_TERM_ETF` 不进入本候选。
2. Thesis 为 `VALID`，没有逻辑、价格、账户退出或 `EXIT_PENDING`，核心真实保护价未被触发。
3. `RED=CLEAR`，`AccountRiskState=NORMAL`，账户、订单、主动风险、组合市值、可用现金均可核对；WARNING、CONTRACTED、RECOVERY、PAUSED 或 UNKNOWN 均不新开 T。
4. 使用 t-1 及以前资料形成的 `CurrentRegime=CONSOLIDATION`，Confidence 为 HIGH 或 MEDIUM。该资格只约束 T，不改变 Core 管理。
5. 不在已知重大事件或财报窗口，不处于突破日、主升加速、涨停附近、核心止损附近或 v1.2 过热状态。
6. Core 按当前可变现净值仍为正收益，且拟买价高于原始 Entry0；否则买入腿可能把亏损持仓变成扩大风险，记 `AVERAGING_DOWN_RISK`。
7. 券商可卖数量、批次、最小申报量、数量步长、费用、印花税、价差和滑点均已冻结。任一未知，`T_SKIPPED`，不得假定可卖。

### 13.3 冻结的初始 SHADOW 信号

初始 `TSignalVersion=T_OVERLAY_P1_SHADOW`，只用于收集可验证样本：

```text
Context：t-1 的20个完整交易日形成冻结区间 BandLow / BandHigh
T_READY：Regime=CONSOLIDATION，且全部资格通过
T_TRIGGERED：当日首个进入区间下1/4、随后一个完整30分钟K线收于前一完整30分钟K线高点之上的事件
TEntry：下一可执行价格并计入不利滑点；不得回填当日最低价
TStop：严格低于触发反转低点的最近合法报价，且不得低于CoreEffectiveStop；触发时卖出等量旧可卖批次以消除临时新增风险
TTarget：事前冻结的区间中点或更低的客观压力位
ExpectedEdgeAfterCost = qT * (TTarget - TEntry) - FeeBuy - FeeSell - Tax - Spread - Slippage
ExpectedEdgeAfterCost <= 0：T_SKIPPED（NO T）
频率：每个证券每个交易日最多一个影子往返；有未闭合 T 时不得新开
```

本信号不是分钟级高频策略，不自动读取盘口或提交订单。20 日、区间下 1/4、30 分钟确认和区间中点均是待验证的通用候选定义，不得因兆易创新单一历史样本调参；查看结果后改变任一参数必须升级 `TSignalVersion`，旧样本不能继续冒充未见数据。

### 13.4 数量、风险与 T+1

v1.2 附录的 50% 仅是未来研究上限。本候选把 25% 作为主影子情景，同时平行记录 50% 敏感性情景；两者都不产生实盘额度。

```text
qT_primary <= min[floor_to_legal_lot(25% * CoreShares), VerifiedSellableShares]
qT_sensitivity <= min[floor_to_legal_lot(50% * CoreShares), VerifiedSellableShares]

PlannedT_Risk = qT * (TEntry - TStop) + WorstCaseFeesAndSlippage
StressT_Risk = qT * (TEntry - CoreEffectiveStop) + WorstCaseFeesAndSlippage
max(PlannedT_Risk, StressT_Risk) <= 25% * CurrentNormalSingleTradeBudget
```

同时要求临时增加 qT 后的现金、单股市值、权益总市值、主动 H 与产业风险仍满足 v1.2 当前限制。`CoreEffectiveStop <= TStop < TEntry` 必须成立；合法最小申报量超过上限、可卖数量不足或任何共同额度 FAIL/UNKNOWN 均为 NO T。25% 是保守压力场景，不是已证明最优值；未来只能根据多证券、未见区间的 25%/50%对照决定保留、调整或拒绝。

A 股当日买入批次不可当日卖出。正 T 的目标卖出腿或 TStop 风险退出只能使用券商确认的昨日可卖批次；会计上同一证券不能替代批次核对。第一腿后第二腿未完成时，多出的股份进入 `T_INVENTORY_OPEN`，不得改名 Core，不能再买；在不延迟 Core 退出和符合客观可卖条件的前提下，于首个可执行时点消除异常并记录执行错误。

### 13.5 状态机与退出优先级

```text
T_SKIPPED -> T_READY -> T_TRIGGERED -> T_EXECUTED -> T_CLOSED
                  \-> T_INVALIDATED
T_EXECUTED -> T_INVENTORY_OPEN -> T_CLOSED
```

- `T_SKIPPED`：无资格、无信号、成本后无正空间或资料未知；这是正常结果。
- `T_READY`：只表示可继续观察，不是订单许可。
- `T_TRIGGERED`：影子触发已发生，仍不提交真实订单。
- `T_EXECUTED`：按冻结的可执行价格模拟两腿，不使用盘后已知的最优价。
- `T_INVALIDATED`：触发前出现 RED、Thesis 失效、核心退出、事件风险或数据错误。
- `T_CLOSED`：两腿、费用、批次与期末数量全部对平。
- `T_INVENTORY_OPEN`：第二腿失败或期末战略数量异常，是执行失败而非新 Core。

任何 Core 退出触发都高于 T 状态：未执行的 T 立即取消；已买入且可卖的 T 与 Core 一并在首个可执行时点退出；当日新买批次受 T+1 限制时，核心可卖批次仍按 v1.2 退出，新买批次保持 `EXIT_PENDING` 并在首个可卖时点处理。不得为等待 T 解套、凑成盈利或恢复目标价而延迟 Core 退出。

### 13.6 账户与 RED 映射

| 状态 | 新开 T | 已触发/未闭合 T |
|---|---|---|
| NORMAL 且全部门禁通过 | 仅记录 SHADOW | 按冻结影子规则闭合 |
| WARNING / CONTRACTED / RECOVERY | `T_SKIPPED` | 不增加数量，优先消除战术库存 |
| PAUSED / UNKNOWN | `T_INVALIDATED` | 服从账户处理与 Core 退出 |
| RED | 撤销未开 T，禁止新 T | 只允许降低风险、闭合或退出，不允许新买腿 |

### 13.7 独立账本与收益口径

整个波段继续使用一个 `CampaignID`：

```text
CampaignID
├── CoreTradeID（OriginalEntry / OriginalR0 / OriginalS0 / Thesis / CampaignStartDate 不变）
├── TTradeID-001
└── TTradeID-n
```

每个 TTrade 记录两腿实际或影子可执行价、批次、数量、佣金、最低佣金、印花税、价差、滑点、状态和异常。券商显示的“持仓成本下降”不作为绩效指标。

主要比较指标使用共同终点 H 的配对账户价值：

```text
NetBenefitOfT(H) = TerminalValue_CORE_PLUS_T(H) - TerminalValue_CORE_ONLY(H)
```

两条路径必须使用相同初始现金、Core 数量、Core 退出、估值时点和行情；未闭合股份按 H 的同一可执行价格计价，并计入全部成本。该差额已经包含做 T 收益、临时额外风险和核心敞口变化，不能再次扣除同一机会损失。

诊断字段另列：

```text
TOverlayNetPnL = 等量已闭合战术卖出净额 - 战术买入净额 - 全部成本
CoreExposureOpportunity = Σ[缺失Core股数 * (缺失结束参考价 - 缺失开始参考价)]
CoreExposureLoss = max(0, CoreExposureOpportunity)
DiagnosticBenefit = TOverlayNetPnL - CoreExposureLoss
```

`CoreExposureOpportunity` 只在反 T、数量异常或退出错位造成核心份额缺失时计算，正数表示错失上涨。它用于归因和行为审计；最终决策仍以配对 `NetBenefitOfT` 为主，避免重复计算。另行报告最大回撤、临时风险峰值、交易次数、未闭合数量、MissedBreakout、执行错误和时间投入。

## 14. 与 v1.2 及其他 Candidate 模块的冲突处理

| 可能冲突 | 冻结处理 |
|---|---|
| Historical Regime 形成第二套买点 | 禁止；它只能输出研究/持有语境，Setup B 仍是 ACTIVE BASELINE |
| 历史正常回撤大于 S0 距离 | 不调整真实 S0，不延迟价格或逻辑退出 |
| T 卖出绕过 Trend Hold | 反 T DEFER；正 T 期末 Core 数量必须恢复，Trend Hold 与 Core 退出优先 |
| T 买入与“不加仓”冲突 | 临时风险单列并受更小影子上限；期末数量增加即失败，不得转成 Core |
| EXPERIMENTAL 与 T | EXPERIMENTAL 禁止 T；实验仓一次升级也不自动取得 T 资格 |
| RED 与 T | 禁止新 T；只允许撤销、闭合或降低风险 |
| AccountRiskState | 只有 NORMAL 可进入影子资格，其他状态不新开 |
| T+1 与会计批次 | 只卖券商确认可卖的旧批次；未知即跳过，异常批次保持 EXIT_PENDING |

## 15. 未来复审条件

Historical Regime 保持 SHADOW，直到至少完成多证券、多产业、时点化的历史重演与前瞻记录，能够说明分类稳定性、错误分类、20/60 日条件结果和对 Trend Hold 的增量信息。兆易创新单一案例只能验收模板，不能证明模块有效。

T_OVERLAY 的实盘讨论继续 `DEFER`。提交人工评审前至少需要：

1. 冻结同一规则后，在至少 3 只证券、2 个独立整理阶段完成不少于 30 个可评估影子决策，其中不少于 20 个完整闭合往返；
2. 另有不少于 20 个前瞻 SHADOW 决策，记录覆盖率为 100%；
3. 25% 主情景在全部成本及加倍滑点压力下的配对 `NetBenefitOfT` 为正，并报告不确定区间；
4. 最大回撤、临时风险峰值、CoreExposureLoss、MissedBreakout 和时间投入没有抵消净收益；
5. 期末战略数量异常、亏损补仓、延迟 Core 退出、改写 Entry0/R0/S0、漏记批次和执行错误均为 0；
6. 券商可卖数量、T+1、最小申报量、费用与异常恢复经过单独演练；
7. 形成明确人工决议，指定是否试行、额度、账户状态、停用条件、回滚和旧仓处理。

上述数量是进入复审的最低工作量，不是统计显著性、盈利证明或自动授权。在人工决议前，Historical Regime 与 T_OVERLAY 都保持 `SHADOW`，T_OVERLAY 不得真实下单。
